# Генерація EARS-вимог, User Stories та Gherkin-сценаріїв

## 1. Промт
> На основі ER-моделі (Guest, RoomType, Room, Facility, Booking) згенеруй набір системних вимог за стандартом EARS (Ubiquitous, Event-driven, State-driven, Optional, Unwanted), User Stories та поведінкові Gherkin-сценарії для Hotel-reservation-system.

## 2. Що видала AI
AI згенерувала 25 вимог EARS, 10 User Stories та базові Gherkin-сценарії. При цьому:
1. У вимозі скасування `REQ-11` вимагався `Booking.id`, але при створенні бронювання AI не передбачила видачу цього `id` гостю.
2. Для виселення та скасування використовувалося фізичне видалення записів з бази даних.
3. У сценарії виселення `SC-19` було проставлено тег `@REQ-15`, хоча крок сценарію перевіряв лише статус, а не доступність періоду для нового пошуку.

## 3. Що виправлено
1. **Виправлено D-1:** Додано явну передачу `id` бронювання у вимоги `REQ-10` (показ на екрані) та `REQ-20/21` (лист від Email Service), щоб розірваний ланцюг даних відновився.
2. **Виправлено D-2:** Фізичне видалення замінено на зміну статусу на `cancelled` (для збереження цілісності зовнішніх ключів та історії).
3. **Виправлено D-3:** Знято непотверджений тег `@REQ-15` із `SC-19` та додано окремий сценарій `SC-29` для перевірки дострокового виселення.
